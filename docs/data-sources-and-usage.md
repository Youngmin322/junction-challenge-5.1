# MOPS 데이터셋·API 사용 원장

> 기준: 2026-08-23 `main` (`9fe0b64`) 코드, 자동 테스트, 공식 제공기관 명세 및 팀 실호출 기록
>
> 목적: 발표 중 “어떤 데이터를 실제로 썼는가?”라는 질문에 코드와 같은 답을 하기 위한 문서

## 1. 먼저 구분할 네 가지 상태

MOPS에서는 “API를 찾았다”와 “위험영역 계산에 썼다”를 같은 뜻으로 사용하지 않는다.

| 상태 | 뜻 | 발표에서의 표현 |
| --- | --- | --- |
| **계산 입력** | 입자 출발점, 이동장 또는 감시격자 판정에 실제로 들어간 값 | “계산에 사용했습니다” |
| **맥락 정보** | 화면·Copilot이 상태를 설명하지만 이동 계산값을 바꾸지 않는 자료 | “판단 맥락으로 조회합니다” |
| **검증·참고** | 유향 규약이나 구현을 대조하지만 한울 이동장으로 사용하지 않는 자료 | “교차검증에만 사용했습니다” |
| **후보·미사용** | 존재는 확인했지만 위치·해상도·시각·권한 또는 데이터 의미가 맞지 않아 제외한 자료 | “검토했으나 현재 계산에서는 제외했습니다” |

또한 자료의 출처 상태를 `LIVE`, `CACHED`, `SYNTHETIC`으로 분리한다. 기본 데모는 인증키 없이 재현할 수 있도록 `CACHED` 관측과 `SYNTHETIC` 시나리오를 사용한다. 실호출을 켜더라도 실패한 LIVE 자료를 fixture로 조용히 바꾸지 않는다.

## 2. 현재 데모 계산에 실제로 들어가는 데이터

| 우선순위 | 필요한 정보 | 현재 구현 입력 | 필수 변수 | 실제 역할 | 현재 한계 |
| --- | --- | --- | --- | --- | --- |
| 1 | 해파리 군집 관측정보 | `historical_observation_fixture` 또는 명시적으로 등록한 `scenario_seed_synthetic` | 관측/기준시각, 위·경도 | 입자 member의 출발 위치 결정 | 기본 관측은 2019년 과거 재생 1건이고, 실행용 seed는 합성값이다. NIFS 목록을 점좌표로 바꾸지 않는다. |
| 2 | 시간별 면 해류장 | `khoa_roms_live` 또는 `synthetic_field` | 유효시각, 위·경도, 표층 유향·유속, 수온 | member를 이동시켜 **3·6·12시간** 조건부 이동영역 계산 | ROMS는 표층 자료이며 공급 응답에 모델 run time이 없다. 면 커버리지·유향 Gate 통과 때만 선택한다. |
| 3 | 수심·해안 경계 | `synthetic_bathymetry_flat` | 합성 수심, 계산영역 | 수송 엔진의 재현 가능한 데모 경계 | 실제 해안선·수심이 아니다. 따라서 실제 얕은 수역·육지 차단을 재현했다고 말하지 않는다. |
| 4 | 원전 주변 감시구역 | `DEMO_GATE_ONYANG_v1`, `DEMO_GATE_DEOKCHEON_v1`, `DEMO_GATE_NAGOK_v1` | 공개 관측점 좌표, 감시격자, 게이트 선분 | member가 감시격자 또는 게이트를 지났는지 `M of N`으로 판정 | 실제 취수구 위치·기하가 아니며 `facility_geometry`는 `null`이다. |

### 계산 흐름

```text
과거 관측 또는 합성 seed
  → 표층 면 해류장(실측 ROMS가 Gate를 통과하면 ROMS, 아니면 명시적 합성장)
  → 3·6·12시간 member 이동영역
  → 공개 관측점 기반 감시격자·게이트 교차 M of N
```

`M of N`은 확률이 아니다. 정해진 초기 member 중 해당 격자 또는 선분을 지난 수다. 입자 수와 초기 배치가 달라지면 값도 바뀌므로 “위험확률”로 읽지 않는다.

## 3. 확인한 공공데이터 API 전체 목록

### 3.1 해파리·해양환경 — 국립수산과학원(NIFS)

공식 명세: [국립수산과학원 OpenAPI 목록](https://www.nifs.go.kr/openApi/actionOpenapiInfoList.do)

| 내부 source ID | 데이터셋 / API ID | 수집 변수 | 구현 상태 | MOPS에서의 역할 | 계산 사용 |
| --- | --- | --- | --- | --- | --- |
| `nifs_jelly_catalog` | 해파리정보 `jellyList` | 게시판 번호, 제목, 작성자, 등록일 | LIVE 어댑터·캐시·테스트 구현 | 최근 해파리 주간보고/속보가 존재하는지와 갱신시각을 확인하는 **보고서 목록** | **아니오.** 개별 관측 좌표·관측수심·정량밀도가 아니므로 입자 seed로 쓰지 않음 |
| `nifs_redtide_list` | 적조정보 `redtideList` | 조사일시, 진행·특보상황, 원인생물, 조사해역, 생물밀도, 수온 | LIVE 어댑터·캐시·테스트 구현 | 해양생물·수질 상황의 보조 맥락 | **아니오.** 플랑크톤 현존량이나 해파리 먹이량으로 해석하지 않음 |
| `nifs_soo_list` | 정선해양관측정보 `sooList` | 위·경도, 관측일시·수심, 수온, 염분, 용존산소, 영양염 | LIVE 어댑터·캐시·테스트 구현 | 수층 환경을 설명하는 역사·관측 맥락 | **아니오.** 해파리 위치나 군집밀도를 직접 관측하지 않음 |

NIFS 공통 요청 파라미터는 `key`, `sdate(yyyymmdd)`, `edate(yyyymmdd)`다. 구현은 발표일 기준 최근 45일을 조회한다.

```text
https://www.nifs.go.kr/api/OpenAPI_json?id={dataset_id}&key={API_KEY}&sdate={YYYYMMDD}&edate={YYYYMMDD}
```

인증키는 URL·문서·Git에 기록하지 않고 다음 서버 환경변수로만 주입한다.

```dotenv
JELLYGUARD_NIFS_JELLY_KEY=
JELLYGUARD_NIFS_REDTIDE_KEY=
JELLYGUARD_NIFS_SOO_KEY=
```

#### `jellyList`를 “해파리 직접관측 API”라고 부르면 안 되는 이유

현재 구현이 받는 `jellyList` 응답 필드는 `board_idx`, `board_subject`, `board_writer`, `inpt_date`다. 즉 주간보고 게시물 카탈로그다. 국립수산과학원이 현장 모니터링을 취합해 보고서를 만드는 것은 맞지만, 이 엔드포인트가 개별 신고의 좌표·시각·사진·밀도를 반환하는 것은 아니다.

| --- | --- | --- | --- | --- | --- |

KHOA 키는 네 API가 함께 쓰는 서버 환경변수 하나로 관리한다.

```dotenv
JELLYGUARD_KHOA_KEY=
```

#### 왜 부이보다 ROMS가 이동 계산의 중심인가

부이는 특정 지점에서 실제로 측정한 값이라는 장점이 있지만, 점 세 개만으로 입자 주변 모든 위치의 속도를 보간하기 어렵다. ROMS는 bbox 안의 여러 위·경도와 시간별 값을 제공하므로 면 이동장 후보가 된다. 대신 모델 표층값이므로 실제 수직 이동·취수구 국지 유동을 표현한다고 주장하지 않는다.

### 3.3 해파리 과거 출현자료 — CACHED fixture

| 항목 | 내용 |
| --- | --- |
| 현재 데모 레코드 | `OBS-HANUL-HIST-001` |
| 원 관측일 | 2019-07-11 |
| 제공 정보 | 시각, 점 좌표, 출현 `detected` |
| 자료 상태 | `CACHED` / 과거 직접관측 재생 |
| 사용 목적 | 검색 계약·지도 관측 심볼·출처 상태를 재현하고, 현재 관측과 혼동하지 않는지 검증 |
| 금지 해석 | 현재 군집, 실시간 탐지, 노무라 종 확정, 정량 생물량 |

이 레코드는 과거 공공 출현보고 형식을 재현한 fixture다. 화면과 Copilot은 “현재”가 아니라 “2019년 과거 관측”이라고 표시해야 한다.

## 4. 원전 위험구역 설정 요소: 사용한 것과 아직 쓰지 않은 것

현재 구현의 정확한 명칭은 **“원전 위험구역”이 아니라 “한울 주변 공개 감시격자·가상 게이트”**다.

| 요소 | 데이터/출처 | 현재 상태 | 사용 이유 또는 제외 이유 |
| --- | --- | --- | --- |
| 한울 주변 관측 기준점 | KHOA HB_0007·0008·0009 공개 좌표 | **사용** | 민감한 시설 좌표 대신 공개된 해양관측점 중심으로 프로토타입 감시격자를 구성 |
| 한울 주변 면 해류 | KHOA ROMS | **조건부 사용** | member가 어느 감시격자 방향으로 이동하는지 계산 |
| 한울 인근 점 해류·수온 | KHOA `twRecent` | **맥락 사용** | 가까운 관측소 상태를 보여주되 면 수송장으로 확대하지 않음 |
| 원전 가동 상태 | [한국수력원자력 원자력발전소 상태 API](https://www.data.go.kr/data/15157718/openapi.do) | **확인했으나 미연동** | 호기 운전상태는 제공하지만 정지 원인·취수구 부하·차압을 제공하지 않는다. 이를 해파리 영향 라벨로 쓰면 인과가 틀릴 수 있음 |
| 실제 취수구 위치·기하 | 비공개/미확보 | **미사용** | 현재 `facility_geometry: null`; 공개 데모는 실제 시설 경계가 아님 |
| 실제 스크린 차압·취수유량·수거량 | 운영자 시설자료 | **미확보·미사용** | 해파리 유입량·막힘·시설부담을 계산하려면 필요하지만 현재 공개자료에는 없음 |
| 실제 수심·해안선 | KHOA 등 후보 API | **미연동** | 현재는 합성 평탄 수심이라 실제 육지·얕은 수역 회피를 주장할 수 없음 |

KHNP 원전 상태 API는 한울본부를 포함한 본부·호기 운전상태를 제공하는 공식 API다. 그러나 현재 MOPS 계산과 source registry에는 들어 있지 않다. 향후 대시보드 운영 맥락으로 붙일 수는 있지만, 출력 변화만으로 “해파리 때문에 정지했다”라고 판단할 수는 없다.

## 5. “수면 위 / 수면 밑 / 이동”으로 설명할 때의 정확한 분류

### 수면 위에서 보이는 해파리

- 현장 사진·목시·영상·신고 좌표가 직접관측이다.
- 현재 공개 LIVE 연결인 NIFS `jellyList`는 개별 직접관측 피드가 아니라 주간보고 목록이다.
- 현재 데모 지도에는 과거 좌표 관측 fixture가 있으며 `CACHED`로 표시한다.

### 수면 밑에서 살기 좋은 환경

- NIFS `sooList`의 수온·염분·용존산소·영양염은 해파리 분포를 해석할 때 참고할 환경자료다.
- `redtideList`는 원인생물·조사해역·적조 생물밀도·수온을 제공하는 적조 사건자료다.
- 두 자료 모두 “그곳에 해파리가 있다” 또는 “대량군집이 발생한다”를 직접 증명하지 않으므로 현재 수송식의 가중치로 넣지 않는다.

### 해파리 이동

- 현재 계산에 쓰는 동역학은 **표층 해류**다.
- 바람·파랑은 구현 후보 맥락이지만 현재 member 이동식에는 들어가지 않는다.
- 울릉도–독도 소용돌이는 현재 제품 입력과 차별점에서 제외했다. 특정 소용돌이가 한울의 해파리 유입을 만든다는 검증 근거가 없기 때문이다.

## 6. 발표용 한 장 요약

| 질문 | 짧은 답 |
| --- | --- |
| 해파리 데이터는 무엇을 썼나? | NIFS `jellyList`로 공식 주간보고 목록과 갱신상태를 조회하고, 지도·계산 데모는 2019년 과거 좌표 관측과 명시적 합성 seed를 사용했다. `jellyList`를 실시간 군집 좌표로 사용하지 않았다. |
| 해류 데이터는 무엇을 썼나? | 한울 주변 KHOA ROMS 표층 면 유동장을 수집·검사하고, 면 커버리지와 유향 Gate를 통과할 때만 3·6·12시간 이동 계산에 쓴다. 인근 `twRecent` 부이는 점 맥락이다. |
| 적조·정선해양 자료는 왜 받나? | 해양환경 맥락과 향후 분석 후보를 제공하기 위해서다. 현재는 해파리 위치나 수송을 결정하는 입력이 아니다. |
| 원전 가동상태도 썼나? | 공식 API 존재는 확인했지만 현재 MVP에는 연동하지 않았다. 운전상태만으로 해파리 영향 원인을 판단할 수 없기 때문이다. |
| 실제 취수구 위험구역인가? | 아니다. 공개 관측점 기반 감시격자·가상 게이트다. 실제 취수구 기하와 시설 임계값은 사용하지 않았다. |
| 결과가 위험확률인가? | 아니다. 조건부 이동영역과 감시격자·게이트를 지난 member의 `M of N`이다. |

## 8. 인증키 취급

- 실제 키는 로컬 `.env`에만 저장한다.
- GitHub, 발표자료, 화면 URL, 로그에는 키 원문을 넣지 않는다.
- 브라우저에 노출되는 `NEXT_PUBLIC_*` 변수로 공공데이터 키를 전달하지 않는다.
- 발표자료에는 인증키 값 대신 `발급 완료` 또는 환경변수명만 표시한다.
- 키가 유출됐다고 판단되면 제공기관에서 폐기·재발급한다.
