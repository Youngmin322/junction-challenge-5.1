# 한울원전 조건부 접근 우선순위 지도

한울원전의 실제 위치 맥락 위에 **더미 관측 군집과 합성 해류**를 올려, 계산 흐름을 설명하는 해커톤용 웹 데모입니다. 기본 시나리오는 울진 동해안 외해의 군집이 서쪽 취수구 감시선으로 접근하도록 만들어졌습니다.

> 한울원전 위치를 제외한 관측시각·군집·해류·수심 가정·경로·도달 결과는 모두 시연용 합성 데이터입니다. 화면의 연결률과 ETA는 실제 막힘 확률, 생물량 또는 시설 위험도를 뜻하지 않습니다.

## 실행

```bash
npm install
npm run demo
```

브라우저에서 Vite가 출력하는 주소를 엽니다. 배포 번들은 `npm run demo:build`로 생성합니다.

## 화면 읽는 법

시간과 색은 서로 다른 값을 나타냅니다.

- 시간 슬라이더: 선택한 시간까지 입자가 실제로 지나간 격자와 경로만 표시
- 진한 적색: 지나간 격자 중 취수구 2 km 이내
- 적색: 취수구 2–5 km
- 산호색: 취수구 5–12 km
- 옅은 살구색: 취수구 12 km 초과

원전에서 가깝다는 이유만으로 색칠하지 않습니다. 합성 입자가 지나간 격자만 `approachPriority`를 받으므로, 색칠된 영역은 **주어진 흐름 아래 형성된 조건부 접근 회랑**입니다.

기본 한울 시나리오에서는 72개 더미 입자가 약 16–18시간 사이에 가상 감시선을 통과하도록 설정했습니다. 이는 UI와 계산 과정을 설명하기 위한 의도적인 설정입니다.

## 제공 시나리오

- `한울원전 접근 흐름`: 실제 한울 위치 맥락 + 서쪽을 향하는 합성 해류
- `동쪽 확산`: 일정한 동북동 가상 흐름
- `조류 반전`: 4시간 후 남동쪽으로 흐름 변화
- `해안 차단`: 가상 해안선·얕은 수역에서 일부 입자 이동 중단

## 실제 데이터로 교체하는 경계

지도는 해류 API를 직접 호출하지 않습니다. [scenarios.ts](./src/scenarios.ts)가 엔진의 `SimulationInput`을 만들고, 지도는 계산된 GeoJSON만 받습니다. 따라서 아래 provider를 실제 어댑터로 바꿔도 렌더러는 그대로 사용할 수 있습니다.

| 입력 | 실제 어댑터의 책임 | 연결 위치 |
|---|---|---|
| 관측 군집 | 시각·점/폴리곤·종·수심·신뢰도를 정규화 | `seed` |
| 외해 해류 | 시각·위치·수심에 맞는 `u/v` 반환 | `offshoreFlow.velocityAt` |
| 연안 조류 | 연안 영역에서 외해장을 교체하거나 확인된 잔차만 합산 | `nearshorePolicy` |
| 수심·해안선 | 다음 입자 위치의 통과 가능 여부 판정 | `navigability.canTraverse` |
| 감시 게이트 | 취수구 전면 선분 또는 중심·폭 정의 | `gate` |

해류와 연안 조류를 무조건 더하면 조석이 중복될 수 있습니다. 실제 연동 시 `replace` 또는 `residualAdd` 정책을 원본 모델 정의에 맞게 선택해야 합니다.

## 지도 출력 계약

- `earliestArrivalBands`: 격자별 최초 도달 시간
- `buildApproachPriorityBands(...)`: 위 격자에 취수구 거리와 `approachPriority` 추가
- `particleTrajectories`: 앙상블 입자 경로
- `horizonSummaries`: 2/4/24/48시간 조건부 게이트 연결 비율과 ETA p10/p50/p90
- `snapshots`: 시간별 동적 연결영역

실제 API가 붙어도 이 GeoJSON 출력 계약을 유지하면 웹 코드를 다시 만들 필요가 없습니다.
